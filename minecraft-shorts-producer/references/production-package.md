# Complete Production Package

Use this after the user selects an idea or supplies a specific concept. Deliver the package in this order.

## 1. Creative Core

- Working concept
- Primary format and emotional engine
- One-sentence viewer promise
- Target length
- Minecraft edition/version if relevant

## 2. ElevenLabs Script

Provide one complete, copy-ready narration block using `elevenlabs.md`. The script must resolve its promise before the CTA.

## 3. TTS Direction

State mood, pace, emphasis, slow-down point, and pause placement. Do not contaminate the copy-ready block with these notes.

## 4. Recording And Edit Blueprint

Use a production-ready table:

| Time | Gameplay/visual | Voiceover beat | On-screen text | Edit/SFX |
|---|---|---|---|---|

Requirements:

- Frame zero contains the strongest visual proof.
- Captions are usually 3-6 words and remain inside the safe vertical area.
- Change framing, action, zoom, caption, or sound when attention would otherwise flatten; do not cut randomly every second.
- Identify footage that must be recorded, recreated, replayed, or shown in split-screen.
- State any world setup, command, seed, item, mob, replay-mod, edition, or version requirement.
- Include a clean loop instruction when a loop fits naturally.

## 5. Upload Packaging

- 3 curiosity-first title options, normally 45-70 characters
- 1-3 line description that clarifies the clip and asks one natural question
- 3-5 relevant hashtags without stuffing
- safe music mode plus exact SFX direction
- first-frame text
- thumbnail/channel-grid suggestion only when useful; Shorts-feed discovery does not depend heavily on thumbnails
- related-video recommendation that complements this Short

Do not rely on URLs in Shorts descriptions or comments. When the channel has advanced feature access, recommend YouTube's Related Video field for a clickable path to another Short, video, or live stream.

## 6. Growth Test

Include:

- why viewers should stay
- why a viewer might subscribe
- one A/B variable only, such as first frame, hook wording, length, or CTA
- the primary metric to inspect
- a `Data basis` line: channel data, current research, verified Minecraft source, or best-effort evergreen assumption

## Quality Check

Before delivery confirm:

- Can a cold viewer understand frame one without context?
- Does the narration continue the visual promise immediately?
- Is the payoff visible rather than merely claimed?
- Is the idea meaningfully different from generic Minecraft clones?
- Is every factual claim verified or clearly framed as an experiment?
- Does the CTA create a real next action?
- Can the user actually record every requested shot?
