# Shorts TTS Scriptwriter

## Overview

Create compact, natural voiceover scripts and complete upload packages for faceless gaming and brainrot YouTube Shorts. Optimize for first-second retention, replay, comments, subscriber conversion, and monetization-readiness rather than polished long-form narration.

## Workflow

1. Identify the game, clip type, target length, desired tone, and whether the user has channel analytics or past video data.
2. If current trends, updates, codes, player counts, music, or game choices matter, browse current sources before recommending topics or packaging.
3. If channel data is provided, apply `references/channel-data.md` before choosing formats, titles, and CTAs. If channel data is requested but unavailable, ask for an export, screenshots, or a channel link; then continue with best-effort trend research if the user wants speed.
4. If the user gives no game, pick from the current priority lanes in `references/game-lanes.md`.
5. Choose a script format from `references/formats.md`.
6. Write for TTS using `references/tts-style.md`: short spoken lines, clean punctuation, no tongue-twisters, and clear emotional beats.
7. Package the Short using `references/packaging.md`: title, description, hashtags, music/sound choice, posting notes, and analytics hypothesis.
8. Deliver scripts in a production-ready table unless the user asks for a single script.

If the user asks what games, trends, sounds, titles, descriptions, or upload strategy to target now, browse current sources first. Gaming trends and sound choices change quickly.

## Default Output Format

For each Short, provide:

| Time | Visual | Voiceover | On-screen text |
|---|---|---|---|
| 0-2s | The strongest proof, rare item, fail, steal, or outcome | One sharp hook | 3-6 word hook |
| 2-8s | Setup or first step | Explain the stakes | Key noun/number |
| 8-18s | Main proof/action | Escalate with surprise | Action caption |
| 18-28s | Payoff/result | Land the result | Result caption |
| End | Loop frame or comment prompt | Soft CTA | Part 2 / comment CTA |

Also include:

- `Title`: 45-70 characters, curiosity-first.
- `Description`: 1-3 short lines with the game, clip promise, and a natural comment prompt.
- `Hashtags`: 3-5 niche tags, no spam.
- `Music/sound`: exact direction, such as trending in-game sound, tense riser, goofy meme sound, SFX-only, or low-volume fast beat.
- `TTS direction`: pace, emotion, and pause notes.
- `Packaging reason`: why the title/description/music fit the clip and audience.
- `Data basis`: note whether the idea came from current research, provided channel data, trend inference, or a best-effort assumption.
- `Retention note`: why the viewer should keep watching.

## Script Rules

- Start with the result, rare thing, danger, or contradiction; never start with "Today I am going to".
- Keep most Shorts between 15 and 35 seconds unless the user requests a longer script.
- Use spoken language that sounds like a real player talking fast, not a documentary narrator.
- Make one promise per Short and pay it off clearly.
- Use one emotional engine: greed, danger, curiosity, revenge, flex, failure, shock, or discovery.
- Prefer specific game nouns over generic claims: item names, map names, levels, bosses, ranks, updates, codes, pets, seeds, weapons, and characters.
- Use a soft CTA only after the payoff: "comment the next game", "part two?", "would you risk this?", "subscribe before they patch it".
- Avoid fake giveaways, fake codes, fabricated patch notes, harassment, slurs, sexualized minors, or instructions to scam/exploit real players.
- Do not invent channel analytics. If past performance data is unavailable, label recommendations as trend-based or assumption-based.
