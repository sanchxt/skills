# Channel Data

Use this when the user provides analytics, channel links, video links, screenshots, CSV exports, or notes about past Shorts performance.

## Data To Request Or Read

Prefer these fields:

- video title
- game/topic
- publish date and time
- views
- impressions or shown in feed, if available
- viewed-vs-swiped or choose-to-view rate
- average view duration
- average percentage viewed
- retention graph screenshots, if available
- likes, comments, shares
- subscribers gained or lost
- traffic source
- sound/music used
- description and hashtags

If the user has no export, ask for screenshots of the best 10 and worst 10 Shorts from YouTube Studio. If even that is unavailable, continue with trend research and clearly label it as not based on channel history.

## How To Use Past Data

1. Group videos by game, hook type, format, length band, music type, and CTA.
2. Identify winners by subscriber gain per 1,000 views, then retention, then viewed-vs-swiped.
3. Identify false winners: videos with high views but weak subscriber gain, weak retention, or poor comments.
4. Reuse winner patterns, not exact wording.
5. Avoid repeating losers unless a single variable can be fixed, such as hook, length, or topic.

## Decisions From Data

- If viewed-vs-swiped is weak: rewrite the first frame, title, and first voiceover sentence.
- If retention drops early: shorten setup and move proof earlier.
- If retention is strong but subs are weak: pick a more repeatable game/series identity.
- If comments ask for a specific game, update, item, or part two: prioritize sequels.
- If one music style appears in multiple winners: keep that sound direction for similar clips.

## Output Note

Always include a short `Data basis` line:

- "Based on your channel data: repeats your top-performing hook pattern."
- "Based on trend research: no channel data provided."
- "Mixed basis: current trend plus your best retention format."
