# Formats, hooks, and production

The durations below are starting hypotheses. Choose the shortest version that preserves context, comprehension, and a complete payoff. Format beats, not constant motion, determine cuts.

## Priority formats

| Format | Suggested length | Structure and original work | Main value |
|---|---|---|---|
| Confidence backfires | 12–25s | Authentic confident statement → understandable attempt → reversal → brief aftermath. Add meaningful situation context, not fake speech. | Shares, recognition |
| Horror with a visible clue | 18–35s | Establish what the player misses → hold just enough tension → scare/reaction → optional annotated replay showing the clue. | Suspense, rewatch |
| Accidental brilliance/failure | 12–25s | Show goal → unexpected cause → outcome; replay only if it explains why it happened. | Surprise, shares |
| One consequential update | 15–30s | State player consequence → show before/after or direct evidence → version/availability → practical takeaway. | Saves, return visits |
| One overlooked detail | 20–35s | Exact detail question → original frame → zoom/annotation → bounded interpretation and proof. | Curiosity, discussion |
| Then versus now | 20–40s | Same action in two versions → label matched conditions → show difference → concise verdict. | Clarity, discussion |
| Two reactions to the same reveal | 20–40s | Identify the identical reveal → contrasting genuine reactions → original comparison/insight. Avoid invented disputes. | Personality, comparison |
| Deadline/reward alert | 12–25s | Name benefit and eligibility → steps → exact expiry and region/time zone where published. | Saves, utility |
| Skill or luck? | 15–30s | Goal and constraints → uninterrupted outcome → replay exposing mechanism → specific question. | Discussion |
| A co-op game worth trying | 15–30s | Show its distinctive mechanic → one entertaining consequence → title/platform/player count after verification. | Shares to friends |
| Myth check or rumor check | 20–40s | Specific claim → evidence/test → conclusion and uncertainty. No invented experiment. | Trust, saves |
| Three useful changes | 25–45s | Strongest change first → two distinct useful changes → who benefits. Show each change, not a scrolling changelog. | Utility |

Experiments: recognizable in-game meme, harmless prediction-and-reveal, distinctive NPC behavior, sound/detail comparisons, game-character actor/developer explanation, viewer-submitted clip of the week. Use verified assets. A personality interview is relevant when it changes how viewers understand the game, not merely because a celebrity appears.

Deprioritize exhaustive update lists, interchangeable screaming clips, unverified leaks, generic rankings, compilation filler, and unrelated streamer drama. A ten-item list needs ten strong items; often the best single item makes the better Short.

## Hooks

Create different mechanisms, not synonyms. Pair text with the visual evidence it points to. Adapt these templates only when the footage/facts support them:

- Threat missed: "He checked every door except this one."
- Confidence reversal: "He called this the easy part."
- Goal under pressure: "One teammate. No heals. One exit."
- Visible comparison: "Same weapon. Before and after the patch."
- Useful consequence: "Check this before your next ranked game."
- Precise curiosity: "Watch the mirror behind him."
- Evidence distinction: "What the trailer actually confirms."
- Contrast: "Same reveal. Two very different reactions."
- Unexpected cause: "The enemy wasn't what ended this run."
- Information payoff: "The date returning players need."
- Social recognition: "Every squad has this teammate."
- Mechanic appeal: "This co-op game lets your friend do this."

Use real names when recognition helps; name the game early when it clarifies the premise. Don't use a famous name to hide a dull moment. Avoid unsupported "everyone", "nobody noticed", "rarest ever", fake counts, generic "you won't believe", and "wait until the end." Avoid fake quote marks around original editorial copy.

Before selecting a hook ask: Does a stranger understand it? Does the opening show the relevant subject? Is the gap specific? Is the payoff real? Would the hook remain honest after viewing the source in context?

## Example edit plans (templates, not verified clips)

### 20-second streamer reversal

| Edit time | Picture/text | Audio |
|---|---|---|
| 0–2s | Relevant gameplay plus a short original premise; preserve streamer facecam if the expression matters | Enter on the real setup statement |
| 2–7s | Necessary attempt/goal, remove dead travel | Source dialogue/game sound |
| 7–14s | Consequence and reaction, both readable on phone | Preserve timing and reaction |
| 14–18s | Aftermath or one replay that explains a previously missed cause | Original sound; avoid an irrelevant song drop |
| 18–20s | Finish the joke; optional short verdict | End after the payoff, without a padded outro |

A simple highlight may still have low originality despite this structure. Add an actually useful original context/analysis layer where suitable; assess candidly instead of pretending that a timeline solves reuse.

### 24-second visual news

| Edit time | Picture/text | Audio |
|---|---|---|
| 0–3s | Consequence-led headline with game name | Relevant game sound or cleared background |
| 3–10s | One official image/gameplay example + original short explanation | No narrator required |
| 10–18s | Evidence or before/after comparison, clearly labeled | Let footage breathe |
| 18–24s | Who/when/version + useful conclusion | Clean finish |

### 30-second detail analysis

Question → show unaltered frame → identify detail → compare proof → explain what it does and does not establish. A zoom must reveal real information. A repeated shot needs a new purpose.

## Text and audio execution

- Separate verbatim subtitles from original editorial overlays. Correct names, game terms, numbers, and negations manually. Do not invent a transcript when source audio is unavailable.
- Use short phrases, usually one or two lines, with strong contrast. A 3–8-word headline and 6–12-word explanatory card are useful starting ranges, not mandatory counts. Hold text long enough to read while watching the action; shorten copy before speeding the edit.
- Do not ask viewers to read dense explanations and rapid speech captions simultaneously. Stagger the layers or remove one. A whole paragraph over a 7-second loop is not useful information design.
- Keep essential action/HUD, face reaction, and captions visible in vertical crop. Use a stacked game/reaction layout when a full crop would lose meaning. Avoid tiny double panels.
- Retain credited source identifiers; don't erase watermarks to disguise origin. Export the creator's own clean master without added platform UI watermarks.
- Aim for a clean 9:16, 1080×1920 master when source quality supports it, preserving sensible source frame rate. Do not upscale poor source footage and call it high quality. Preview inside both upload interfaces for UI overlap/cropping rather than relying on eternal pixel-safe-area rules.
- Source dialogue is usually the music. Avoid music over the key reaction; control scream peaks and background audio. "Original audio" in an app is not proof of ownership. See rights reference for cross-platform audio.
- Make mute viewing understandable; preserve an enjoyable sound-on version. Use a smooth loop only when it follows a completed payoff.

## Narration when requested or justified

Write like a knowledgeable gamer talking to one person: clear, specific, mildly amused when appropriate. Avoid newsreader intros, grand claims, repeated premise, fake hype, and dense lists. Let an authentic clip carry the strongest emotion.

Deliver one fenced block containing only audible narration. Put sources, timing, clip instructions, pronunciation notes, and uncertainty outside. Calculate actual word count. Estimate duration at a stated natural pace (for example 140–170 words per minute), then add authentic clip time and pauses; the estimate is not a measured render. Do not force a 90-word script into 20 seconds.

Default to plain text with no model-specific performance tags. If ElevenLabs model features, pricing, licensing, or tag syntax matters, verify current official documentation; do not inherit a particular model from another channel. Never clone a streamer's voice or create words that impersonate their real reaction.

If editing actual media is requested, inspect available files and tools, preserve the originals, and deliver the actual rendered output only after checking it. If only a plan was produced, call it a plan.
